## 用途

对投标/招标报价做**可复算**的数值核对：每一步计算都保留输入值、单位、币种、含税口径、公式（expression）、舍入规则与结果，任何人事后都能用同样的输入重跑得到同样的结果。

适用操作：

- 金额加法汇总（`sum`）
- 数量×单价合计（`multiply`，支持多行汇总校验）
- 单位转换（`convert_unit`，万元↔元）
- 按指定规则舍入（`round`，如 `ROUND_HALF_UP` 到分、`ROUND_05UP` 按 0.05 步长）

## 核心原则（违反即拒绝）

1. **十进制精确**：金额解析为精确整数系数（符号×系数×10^指数），加法、乘法、除以 10000 全部在整数域精确完成；不使用二进制浮点，不依赖任何全局精度上下文，不存在中间舍入、上溢、下溢或规范化丢值。`0.1 + 0.2` 恰为 `0.3`。
2. **按已发布契约执行校验**：按 `schemas/input.schema.json` 逐 operation 校验允许字段、必填、类型、数组与嵌套结构；**未知字段一律拒绝**（如 `sum` 携带 `unit`、行内携带 `tax_basis` 这类与口径可能冲突的附加键不猜测语义，拒绝并要求调用方先统一口径后重提）。金额必须为**字符串**形式的十进制数；JSON 整数/浮点/布尔金额拒绝；`rounding` 若出现必须是对象，`rounding:null` 拒绝。
3. **口径不明就暂停，不猜测**：`currency` 必须是已知币种码，`tax_basis` 必须是已知含税口径；不同币种/口径/单位之间的比较暂停并报口径不明，不得混算。
4. **空值不当零**：读不到金额 ≠ 金额为 0。null、缺失字段、空字符串一律拒绝。
5. **只接受有限数并显式设限**：NaN、Infinity、-Infinity 拒绝；数值字符串长度、有效位数（≤64 位）、指数（±500 以内）、求和项数/行数（≤1000）有显式上限，超界结构化拒绝——有限非零数绝不静默当作 0。
6. **不执行表达式**：严禁把输入当代码执行（脚本不使用 `eval`/`exec`/`compile` 处理任何输入）。所有"公式"由脚本按 operation 类型组装并原样记录到输出的 `expression` 字段。
7. **不修改原件；输出排他创建**：脚本只读输入文件。输出仅允许写入**尚不存在**的路径：先对输入与输出做身份与碰撞预校验（规范路径 + 设备/索引节点相同检测，覆盖同路径、符号链接与硬链接），再以排他模式创建输出文件；拒绝已存在的普通文件、符号链接、目录，拒绝输出与输入为同一文件。输出路径校验或排他创建条件失败时不写文件；数据校验拒绝在获准的目标路径上仍可能产生 rejected JSON 到 stdout——须保存并检查 stdout、stderr 和真实退出码。
8. **回显保留原始输入**：输出 `inputs` 中的金额回显是调用方提供的原始字符串（原样保留），公式与结果值另行精确计算；不做依赖精度上下文的有损规范化。
9. **不自动改报价、不代算政策优惠**：本工具只输出复算结果与候选修正值；评审价、优惠折扣等政策性调整不在本工具范围内，算错也不自动等于无效。

## 覆盖策略（明确声明）

- **绝不覆盖**任何已存在的输出文件（普通文件、符号链接、目录均拒绝）；也不接受经符号链接指向其他位置的输出路径。
- 需要重跑同一计算时：更换一个新的输出路径；或由调用方先自行删除旧输出再重跑。**重跑语义由调用方控制，脚本不代为覆盖。**
- 同路径（`--input` 与 `--output` 相同或互为硬链接/链接解析后相同）一律拒绝，避免截断输入原件；无效输入走拒绝路径时同样先做输出路径校验。
- 输出写入中途失败时移除半成品文件，退出码 3。

## 用法

脚本位于 `scripts/recalc.py`（仅 Python 标准库，Python ≥ 3.8）。

```bash
python3 scripts/recalc.py --input <输入.json> [--output <输出.json>]
```

- 不带 `--output` 时，结果 JSON 打印到 stdout。
- 退出码：`0` 成功；`2` 输入被拒绝（契约违规、未知字段、未知币种/口径、空值、非有限数、无法解析、数值超上限等）；`3` 用法/IO 错误（输入读取失败、输出路径安全校验失败、排他创建失败）。
- **不能仅由退出码推断 stdout 一定是 JSON。** 正常计算或可报告的输入校验可能在 stdout 产生结构化 JSON；但参数解析错误、输出大小限制、文件 I/O 失败、输出路径被拒绝等可能只给 stderr。空 stdout 或解析失败不代表通过——调用方必须始终检查实际退出码。
- 指定 `--output` 且目标路径获准时：输入校验失败（退出码 2）可能将 rejected JSON 写入输出文件；输出路径被拒绝（退出码 3）不写文件。
- 调用方须保存每步的原始 stdout、stderr 和真实退出码，以维持完整审计轨迹。

### 输入格式（见 `schemas/input.schema.json`）

公共字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `operation` | 是 | `sum` / `multiply` / `convert_unit` / `round` |
| `currency` | 是 | ISO 4217 三字母币种码，已知集合：CNY、USD、EUR、JPY、GBP、HKD |
| `tax_basis` | 是 | 含税口径：`tax_inclusive`（含税）/ `tax_exclusive`（不含税）/ `not_applicable`（不适用） |
| `rounding` | 否（`round` 操作必填） | `{ "mode", "increment" }`；mode 为 8 种舍入模式名之一，increment 为正的舍入步长字符串（如 `"0.01"` 到分、`"1"` 到元）。字段值为 `null` 拒绝；整体省略表示不额外舍入 |

操作特有字段：

- `sum`：`operands` —— 金额字符串数组（至少 1 项，至多 1000 项）。
- `multiply`：`line_items` —— 每行 `{ quantity, unit_price }`（至少 1 行，至多 1000 行）；行内先算 `quantity × unit_price`，再对全部行求和。行内只允许这两个键。
- `convert_unit`：`amount` + `from_unit` + `to_unit`（`yuan` ↔ `wan_yuan`，两者必须不同）。
- `round`：`amount`（未舍入金额）。

金额一律用**字符串**传递（如 `"1234.56"`），避免 JSON 二进制浮点失真；JSON 整数或浮点金额会被拒绝。除操作载荷与公共字段外的任何键（含任何 `unit`、行内口径字段）都会被拒绝——冲突口径请先在调用方统一后重提。

### 数值上限（显式、可说明）

| 限制 | 上限 | 超界行为 |
|---|---|---|
| 单个数值字符串长度 | 128 字符 | 结构化拒绝 |
| 单个数值有效位数 | 64 位 | 结构化拒绝 |
| 十进制指数 | ±500 | 结构化拒绝（有限非零数不当 0） |
| `sum.operands` 项数 / `multiply.line_items` 行数 | 1000 | 结构化拒绝 |
| 输出 JSON 文本长度 | 128 KiB | 拒绝写出（退出码 2/3） |

### 输出格式（见 `schemas/output.schema.json`）

成功时 `status: "ok"`，含 `expression`（可读公式）、`inputs`（回显：**金额保留调用方原始字符串**）、`result`（含 `value`、`unit`、`currency`、`tax_basis`、`rounded`）、`rounding`（实际应用或未应用的规则）、`warnings`。

拒绝时 `status: "rejected"`，含 `errors`；不给出任何数值结果。

### 口径登记表

多金额比较前，先用《舍入与口径说明》（`舍入与口径说明.md`）中的模板登记每一项的币种、单位、含税口径与舍入约定；登记表不完整时暂停比较。

## 与报价审查流程的衔接

- 复算值与投标书面值不一致时：记录双边数值与公式，给出**候选修正**，标注"是否构成修正以招标文件规则为准"；不宣称无效。
- 大小写金额不一致：同样只记录两个值与差异，交由招标文件的修正规则裁决。
- 政策评审优惠（小微企业、本国产品等）：**不**用本工具凭空计算；如项目已明确给出比例与叠加条件，按条件手工/另行计算，且评审价不替换投标价。
- 候选复算以已列单价与招标数量为条件，不自动替采购人纠价或判断投标有效性。

## 调用与出稿通用规则

> 以下规则适用于任何使用本技能的审查轮次，不依赖特定项目路径或样本答案。

### 每次检查重新加载 Skill

- 每次审查/检查会话开始前，重新读取本 SKILL.md、`schemas/input.schema.json`、`schemas/output.schema.json` 和 `scripts/recalc.py`。不得依赖历史会话或对话历史中的缓存版本。

### 保留用户申报原值

- 用户申报的具体数值（金额、税额、合计等）须原样记录为**申报值**。
- 使用工具独立重算，结果单独记录为**重算值**。
- 计算并记录申报值与重算值之间的**差额**。
- **绝不修改用户申报值以匹配重算结果**——申报值是原始文件的不可变事实。

### 不从差额反推原因

- 发现申报值与重算值不一致时，如实报告：申报值、重算值、差额。
- **不得从差额反推具体原因**（如"舍入错误"、"录入错误"、"税额计算错误"），除非证据直接且唯一支持该结论。
- 原因不确定时，写"原因待核——需进一步调查"。

### 输出位置

- 用户报告、计算中间文件和测试输出必须写入**当前请求中用户明确指定的输出目录**。
- 不得写入 Agent 自身的源目录（agent 根目录、skills/ 等），除非被明确指示。

### 完整命令审计轨迹

- 每次调用 `recalc.py` 须保存并保留：(1) 完整输入 JSON 文件，(2) 完整 stdout，(3) 完整 stderr，(4) 真实退出码。
- 退出码必须从命令实际返回值捕获——不得用 `|| true` 或其他方式掩盖。
- stderr 不得重定向到 `/dev/null` 或以其他方式丢弃。
- 失败的命令也必须如实记录其真实退出码和 stderr。不得事后将失败调用的退出码标为 0。
- 每次调用必须使用唯一的输入文件和唯一的输出文件路径。复用已有输出路径可能导致退出码 3（排他创建失败）——此情况必须记录，不得隐藏。

### 结果语义与口径一致性

- 脚本 `tax_basis` 字段为调用方传入值的忠实回显，脚本自身不改变其语义。调用方必须对每步操作传入与该步骤结果语义匹配的口径。
- 当操作结果为含税金额（如价税合计 = 不含税合计 + 税额）时，`tax_basis` 应为 `tax_inclusive`；用于加法汇总的不含税基数应为 `tax_exclusive`；税额计算本身可标 `not_applicable`。口径与结果语义不匹配时，报告必须指出并修正。
- 不同口径的金额不得直接混加或比较；混合前必须先统一到同一口径。

### 原始输出留痕

- 每步计算保存：① 输入 JSON（完整内容）② 脚本 stdout（完整原始输出，不截断不手写摘要）③ stderr ④ 真实退出码（须捕获脚本真实退出值，不得用 `|| true` 或类似手段掩盖）⑤ recalc.py 文件 SHA-256。
- 报告中引用"完整输出见 xxx"时，该文件必须包含脚本的完整结构化 JSON 输出（含 expression/result/rounding/warnings 等全部字段），不得仅保存输入 JSON。
- 所有文件 SHA-256 在审查报告中列出，用于事后验证工具未被篡改。

### 舍入声明与输入一致

- 报告中声称的舍入模式（如 ROUND_HALF_UP）必须与实际传入脚本的 rounding 参数一致。
- 未传 rounding 参数时，脚本输出 rounding: null、rounded: false；报告不得声称执行了舍入。
- 如需验证舍入功能，应使用独立的非真实投标数据算式显式传入 rounding 参数，与真实报价复算明确区分。

### 证据保留与版本管理

- 同一项目的多个审查轮次各自保留独立目录，不覆盖历史版本。
- 报告中的双边证据须包含精确页码/位置引用（如 B01-P1、I01、T01-P2 R05），不得仅写"投标文件"等模糊指向。
- 技术观察（图像参数、接口数量等）与商务结论明确区分：商务审查员报告视觉差异与数值不一致，最终技术认定由对应专业成员完成。
